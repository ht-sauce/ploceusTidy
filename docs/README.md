## 3. 硬约束清单

> 只写边界，不写偏好。能进清单的只有「违反会导致功能异常 / 数据事故」与「已验证后果的否决项」；常规风格问题交给工具。

| # | 约束 | 违反后果 |
| --- | --- | --- |
| HC-1 | **高内聚低耦合，代码最简洁实现（第一准则）**：同一职责只落一处，依赖单向、最少；取满足需求的最短实现，禁止为假想需求预留抽象层 | 耦合与抽象层层累积，改动面失控，返工成本持续放大 |
| HC-2 | **先读文档再动手**：接需求先读本文件与范围对应文档；未读不得改文件（单行修复除外） | 违反既有约束产出错误实现，返工并污染代码 |
| HC-3 | **文档同步与不一致上报**：新增/删除文件、用途、能力或接口变更时，同批更新 `project-overview.md`、对应 spec 与根 `README.md` 的当前状态；发现 spec 与代码不一致，先报告用户裁决 | 过期规范比没有规范更危险，后续改动会「自信地」照着错误规则执行 |
| HC-4 | **不主动创建文档**：除规范体系已声明的文件外，不得新建 `*.md` / `README.md`，除非用户明确要求 | 文档泛滥、事实分散，维护失真 |
| HC-5 | **禁止全量扫描**：定位文件先查 `project-overview.md`，只精读目标文件与相关章节 | 上下文浪费、改错文件的概率上升 |
| HC-6 | **先对话后改动**：需求理解 → 方案确认 → 硬约束对照完成后，一次性批量执行；禁止边读边改、边对话边改 | 半成品状态被误当成结论，改动彼此冲突 |
| HC-7 | **新依赖须说明用途**：优先用已有依赖满足需求；引入前说明替代方案与必要性 | 依赖膨胀、供应链与维护成本失控 |
| HC-8 | **后端验证未过不落实现**：M0 剪贴板/画布 spike 前，禁止引入 Tauri 业务代码；前端 UX 原型与工具链可在 ADR-001 确认后先行 | 先写后端代码后验证会造成不可逆的技术锁定与返工 |
| HC-9 | **配置收口**【已生效】：端口、密钥、绝对路径、业务参数只能放统一配置层，应用代码禁止字面量 | 配置散落导致环境不可迁移、凭据泄漏 |
| HC-10 | **整理动作必须可撤销**【v1 只读，不适用】：批量移动、改名、归档须先写操作记录再执行；撤销按记录回滚，禁止无记录的原地修改 | 用户文件被不可逆破坏，产品信任一次性归零 |
| HC-11 | **不可逆操作禁止直达**【v1 只读，不适用】：删除 / 覆盖一律走回收站或备份通道并二次确认；批量执行前默认预演（dry-run）并展示影响面 | 误触即造成数据丢失，无法补救 |
| HC-12 | **只读引用边界**：不得修改、移动、重命名、删除用户文件；读取、打开、定位仅限用户显式导入的引用，解析真实路径后校验，不跟随符号链接越界 | 越界读写或误操作破坏用户文件 |
| HC-13 | **数据不出本机**：文件内容与元数据默认不外传；接入外部 API 必须由用户显式开启并说明发送范围 | 隐私泄漏，触碰个人数据红线 |
| HC-14 | **文件操作异常必须上报**：失败须带「路径 + 操作 + 原因」，禁止静默跳过或只记日志不给用户看 | 用户以为导入/定位完成，实际文件状态不一致 |
| HC-15 | **禁止自增 ID 作为关联键**【已生效】：表关联一律使用自定义 ID，主键与业务关联键均不依赖自增 | 迁移、合并、离线同步时 ID 冲突，关联结构不可重建 |
| HC-16 | **长命令不得死等**【已生效】：单条命令阻塞超过 5 分钟或长时间无输出，必须中断，改用非阻塞执行、缩小范围或拆分验证；禁止连续重试同一条卡死命令 | 时间与上下文被单个命令吞掉，后续改动全部被阻塞 |

**新增硬约束的条件**：出现过一次真实事故或经论证必然出问题；只写「约束 + 违反后果」，编号顺延。

## 4. 工作流（先对话后改动）

1. **读规范**：本文件 + 约定文档 + 范围文档。
2. **理解需求**：复述需求，明确改动范围（具体到文件路径）。
3. **探索现状**：查地图定位后精读相关代码；此阶段只读不写。
4. **方案对照**：逐条对照 §3 硬约束；架构级取舍（跨模块、数据模型、接口、存储）先补 ADR 或更新 spec。
5. **批量改动**：方案确认后一次性完成；文件增删或用途变更同批更新文档。
6. **验证**：验证手段与改动面对应——代码跑检查 / 测试 / 实测，文件操作类改动必须覆盖预演与撤销路径，UI 改动截图验证。
7. **汇报**：改动文件、同步的文档段落、验证结果、需用户手动执行的命令。

**例外**：用户明确要求「先改这一处看看」、单行 typo / 单行 bug、用户已明确指示的删除。
