# 08-adr.md · 架构决策记录

> 只在出现「二选一」的架构取舍时记录。当前尚无已决策条目，待决项见 §4。

## 1. 机制

- **何时必须写**：框架选型、工程结构、存储方案、外部数据源、打包与分发、界面方案等跨模块取舍。
- **每条骨架**：标题 + 状态 + 日期 + 背景 + 决策 + **备选方案** + 后果。
- **备选方案段强制**：逐个记录真实备选及落败原因；不写「它击败了什么」，等于邀请后来者翻案。历史备选无法重建时如实标注。
- **生命周期**：`proposed` → `accepted` / `rejected`（状态行写一行否决原因）；被取代标 `superseded` 并指向新条目。`rejected` / `superseded` 默认保留；防翻案价值消失且经用户确认后才可清理，并在修订记录留痕。
- **分工**：需求侧否决（不做什么）记在 00-overview 范围边界或未来的 REQUIREMENTS 否决专区；方案侧否决（怎么做被否决）记在本文件，一类否决只记一处。
- **事实同步**：后续改动使 ADR 中的路径、名称、默认值过时，同批修正事实，不改决策本身。
- **事故复盘【可选】**：影响面大的踩坑可独立成篇，记录时间线、根因、纠正项与回归护栏；纠正项转成硬约束或 ADR 后在此留链接。

## 2. ADR 模板

```markdown
### ADR-NNN 标题

- 状态：proposed / accepted / rejected / superseded
- 日期：YYYY-MM-DD
- 背景：要解决什么问题，约束是什么
- 决策：选了什么，边界在哪里
- 备选方案：
  - 方案 A：……；落败原因：……
  - 方案 B：……；落败原因：……
- 后果：需要配套改动什么，引入什么风险，何时复查
```
