用户明确：**不做多画布**，后续建议不要带多画布。

结论要点（按优先级）：

1. 关闭窗口不 flush：`useScenePersistence.ts` 350ms 去抖 + `desktopWindow.close()` 直关，无 `onCloseRequested`，最后 <350ms 改动会丢。
2. `StatusBar.tsx` 的「已保存」是写死的，保存失败也显示已保存。
3. 拖入空间自动整理全部成员（`moveNodes` → `arrangeGroupMembers`）**无撤销**，手摆布局会被毁且不可恢复。
4. 导入失败只报第一条（`useImportClipboard.ts` 186-189），违反 coding-conventions §5 失败项汇总。
5. 富文本/文字弹窗取消即丢内容（无 dirty 检测）。
6. 小 bug：`fitView` 有空间时忽略游离对象；滚轮横向 delta 变纵向平移；同一对象多标注只渲染第一个；设置里版本号写死 0.1.1（实际 0.1.2）。
7. 性能：`useVisibleScene` 每次 nodes 变化全量 rebuild rbush（10 万级松手卡）＋ Minimap 抽样、contentBounds 各一次全量遍历。
8. 死代码/假功能：`mountNode`/`unmountNode`/`parentNodeId` 无 UI 入口；`dataJson` 可编辑但画布不消费；`node_get` 命令无调用；Minimap 注释称 memo 但未包裹。

## 上述全部整改（用户：「全改了吧」+ 三条补充需求）

验证：`pnpm lint` / `pnpm format:check` / `pnpm check-spec` / `pnpm build` / `cargo test` 全绿（10 个 Rust 测试通过）。

关键决策（已补 ADR-030 / ADR-031）：

- **保存链路**：`useScenePersistence` 新增 `flush`；关窗拦 `onCloseRequested` → 先落库再 `close()`，失败不放行；`saveNow` 用 `hydrated` 守卫（未加载完写库=清库）；`tauri-api` 广播 saveState → 状态栏三态；能力清单补 `core:window:allow-destroy`（JS 侧 closeRequested 未 preventDefault 时会 `destroy()`）。
- **Ctrl+S**：主窗口立即落库；文字/富文本弹窗内就地保存不关闭（`stopPropagation` 拦住全局）；标注编辑框 Ctrl+S / Ctrl+Enter 保存。弹窗取消若有改动先确认（富文本 dirty 用编辑器 `change` 事件，不比对 HTML，否则规范化会误判）。
- **撤销栈**：`useSceneStore` 改 30 步双栈 + redo，`markHistory(coalesceKey)`，方向键微调 800ms 合并；覆盖移动/微调/改色/改名/连线/标注/导入/整理/删除。快照靠 `latestRef` 读取，命令依赖保持稳定。
- **空间整理**：只在 `groupId` 变化（进出空间）时整理；组内重叠只把被拖对象推开（findFreeOffset 8px 步长）。
- **标注间距**：`NODE_ANNOTATION_HEIGHT` 12→18、`NODE_ANNOTATION_INSET=17`，字号 9→10，标注条底部距框线 5px（原来压线）。
- **性能**：`useVisibleScene` 改常驻 RBush + 按矩形增删（useLayoutEffect 同步）；缩略图缓存 400 张上限；Minimap 真正 memo。
- **手感**：拖动改世界坐标增量（`startWorld` + `panBase/panOffset`）→ 支持边缘 56px 自动平移；滚轮横纵分别平移；方向键微调。
- **顺手**：`fitView` 纳入游离对象；同一对象多标注显示 `+N`；`dataJson.accent` 画成描边（假功能变真）；删掉 `mountNode`/`unmountNode`/`parentNodeId` 客户端逻辑与 `node_get` 命令；版本号由 vite define 从 package.json 注入；导入失败逐条弹窗。
- 文档同批更新：AGENTS.md、README.md、docs/{README,REQUIREMENTS,project-overview}、spec/{02,03,04,08}。
